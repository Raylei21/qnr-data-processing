# 用 qnr-data-processing 出数表 · 新同学操作指南

> 这份指南写给第一次做「问卷出数」的新同学。跟着一步一步走，你不需要会写代码——
> 出数的程序（这个 skill）会替你跑，你只需要把东西准备齐、把口径说清楚、最后核对结果。

---

## 0. 这个工具是干什么的

把「问卷原始数据」变成「能直接汇报的数表」，例如：

| 题目 | 选项 | 总体 频数 | 总体 频率% | 会员等级 Gold 频数 | … |
|---|---|---|---|---|---|
| Q1 性别 | 男 | 200 | 40.6% | 120 | … |
| Q1 性别 | 女 | 293 | 59.4% | … | … |

它能做：清洗（删人/去重/改字段）、分组交叉出表、多选题统计、加权、质量检查、
生成美化版报表。**它只负责"按你说的口径算对"，不会替你猜口径**，所以下面的输入准备是关键。

---

## 1. 动手前，请准备好这「4 + 1」样东西

缺一样就先补齐，否则我会停下来问你，反而更慢。

### ① 原始数据（必给）

- 就是每行一个受访者、每列一道题的那份文件。
- 支持 **Excel（.xlsx / .xls）** 或 **CSV**。
- **必须有一列唯一 ID**（如 `customer_id`、`样本ID`、`id`），要求：不重复、不为空。
- 列名最好带稳定题号（`Q1`、`Q2`…），这样我能自动识别；没有题号也没关系，你告诉我哪列是哪题即可。

### ② 问卷（必给）

- 问卷的 Word / Excel / PDF 截图都可以，我需要看到：**题号、题干、选项列表、单/多选题、跳题逻辑**。
- 它的作用是让我核对选项文字有没有变、多选题怎么编码、谁该跳过哪题，避免我瞎猜。

### ③ 出数规则（必给）

就是「哪些题要出数、按什么拆列、分母怎么算」。用大白话写就行，模板见第 5 节。

### ④ 清洗规则（必给；如果"一个人都不删"，也请明说一句）

删谁、去重、改什么字段。模板见第 6 节。

### ⑤ 加权目标（可选，只有要加权时才给）

要加权时给我：目标人群 + 目标占比 + 这个占比的来源。**没有来源的占比我不会编**。

---

## 2. 重点：原始数据给我哪个版本最省事？

你可能手上有两种导出的数据：

| 版本 | 长什么样 | 给哪个 | 说明 |
|---|---|---|---|
| **文本版** | 选项文字直接填在单元格里，如 `Male`、`Female`；多选是 `价格实惠┋款式多样` | ✅ **优先给这个** | 最省事，见下 |
| **0/1 数字版** | 都是数字码，单选是 `1/2/3`，多选是每个选项一列填 `0/1` | 可以用，但要附问卷/编码表 | 见下 |

**结论：优先给「选项文字直接出现」的文本版。** 三个原因：

1. **规则能直接写选项文字。** 比如清洗"删掉 Q16 选 65 岁以上的"、分组"Gold 会员"，我直接对着文字写，不需要你另外给我"1=男、2=女"这种编码表，出错机会小。
2. **多选自动拆。** 文本版里多选常是一列用 `┋` 连接（`价格实惠┋款式多样`），这个 skill 会自动拆开、逐个选项计数，还认识 `(跳过)` 和 `others〖原话〗`。0/1 版没有这一步。
3. **开放题原话能导出。** 像 `others, please specify〖太贵了〗` 这种"其他+原话"，文本版能自动把原话抽出来单独成表；0/1 版里这些原话往往丢了。

**如果手头只有 0/1 数字版**：没关系，把 0/1 数据和问卷/编码表一起给我就行，引擎照样能出表。
只是输出会先显示数字码，需要我用问卷把码翻译成选项文字，会多一步、也更容易在"哪个码是哪个选项"上出错。

**两个版本都有**：只给文本版即可；若想稳妥，也可以两个都给，我会按 ID 对齐。

> 小提醒：文本版里，**多选题**如果"每个选项一列、填 `是`/`1`"这种，也能处理，但你最好告诉我"这几列是同一道题"。

## 3. 一步一步跟着走（7 步）

下面每一步，谁做什么都写清楚了。「我」= 跑这个 skill 的助手。

### 第 1 步 · 把文件放到一个文件夹

把原始数据、问卷放进同一个工作目录（桌面新建一个文件夹就行）。以后所有结果也会写在附近。

### 第 2 步 · 检查数据结构（我来）

我会先跑一次"只看结构不动数据"的检查：

```bash
python -m qnr_data_processing inspect 原始数据.xlsx --output inventory.json
```

然后我会看：有几个 Sheet、列名、样本量、每个字段长什么样，并跟你确认有没有对不上的地方。

### 第 3 步 · 确认口径（你确认，我问你答）

下面这些如果我拿不准，会停下来问你，你回答即可：

- 哪个是唯一 ID？
- 多选题是"一列 ┋ 连接"还是"每选项一列"？
- 某些题是不是有跳题（没被问到的填了 `(跳过)`）？
- 数据里出现问卷上没有的选项文字，要不要处理？

### 第 4 步 · 自动生成配置草稿（可选）

如果数据列名规范（带 Q1、Q2 这种题号），我可以自动生成一份草稿配置，再人工补规则：

```bash
python -m qnr_data_processing discover 原始数据.xlsx --questionnaire 问卷.xlsx --output task.json
```

### 第 5 步 · 我写任务配置 task.json（我来）

把你在第 1 节给的出数规则、清洗规则、分组、加权，翻译成引擎认识的 JSON。你不需要看 JSON，只要最后核对我列出的口径对不对。

### 第 6 步 · 先校验，不落盘（我来，你一起看）

```bash
python -m qnr_data_processing run --config task.json --validate-only
```

这一步**不产生结果文件**，只是先算一遍，看看：删了多少人、分组人数、有没有非法选项、加权是否收敛。有问题先在这里改，别急着出表。

### 第 7 步 · 正式出表 + 生成美化报表（我来）

```bash
python -m qnr_data_processing run --config task.json
python -m qnr_data_processing report --tables output/...xlsx --config task.json --output 数据分析表_美化版.xlsx
```

要加权版报表就加 `--weighted`。出完后我会把关键数字（输入/清洗后样本量、各规则删了几个人、各分组 Base、质量检查、输出文件路径）汇报给你，并说明有没有小样本被隐藏、有什么限制。

---

## 4. 你会拿到的交付物

一个 Excel 结果文件（可能含多个 Sheet）：

| Sheet | 内容 |
|---|---|
| `tables_long` | 长表：题目 × 选项 × 分组，含频数、Base、频率、加权数 |
| `tables_wide` | 横向对比表：一行一个选项，各分组并排列（汇报常用这张） |
| `tables_weighted` | 加权版横向表（配了权重才有） |
| `open_responses` | 开放题 / "其他"原话（确认授权后才导出） |
| `cleaning_audit` | 每条清洗规则删了几个人 |
| `group_bases` | 各分组的样本量 |
| `quality_checks` | 数据质量问题（非法选项、互斥冲突、跳题违反等） |
| `table_checks` | 频数合计是否等于 Base 的一致性检查 |

外加一个审计 JSON（`audit.json`，方便复核），和一个排版好的「美化版报表」Excel。

## 5. 出数规则：用大白话这样描述给我

照着这个模板填空即可，**越具体越好**：

> 对 **Q1～Q16**（开放题除外）出「频数 + 频率%」。
> 每一题都按下面这些分组拆列：**总体、用户类型（支付/访问/流失）、会员等级（Bronze/Silver/Gold/Diamond）、性别**。
> 单选/矩阵分母 = 该题作答人数；多选题分母 = 至少选了一项的人。
> Q9 按积分认知分成 4 类互斥的分类（我来给规则）。
> 需要的话：Q 满意度题加 T2B（前两档合计）合并行。

需要说清楚的 4 个点：

1. **哪些题**要出数（题号范围或清单）。
2. **按什么拆列**（分组维度，比如"总体 + 会员等级 + 性别"）。
3. **分母怎么算**：单选一般"作答人数"，多选一般"至少选一个"。
4. 要不要 **NET / T2B** 合并行。

---

## 6. 清洗规则：用大白话这样描述给我

同样给模板：

> - 删掉 Q16 选「18 岁以下」的人。
> - 同一个 `customer_id` 只保留「作答时长最长」的一条（去重）。
> - Q9 的选项文字去掉末尾的句号。
> - （没有其他清洗了）

对应到引擎，就是三类：**删人**、**去重**（按某列保留最大/最小值）、**改字段**（去空格/去句号/替换）。没有清洗就明说"不删人、不改字段"。

---

## 7. 出表前，最后过一遍这个检查清单

- [ ] 原始数据有唯一 ID，且无重复、无空值？
- [ ] 问卷 / 编码表已给，选项文字能对上？
- [ ] 出数规则写清了：哪些题、哪些分组、分母、是否 NET？
- [ ] 清洗规则写清了：删谁、去重、改字段？（没有就明说）
- [ ] 多选题的编码方式告诉我了（┋ 连接 还是 每选项一列）？
- [ ] 跳题逻辑（谁该跳过谁）说明了吗？
- [ ] 要加权的话，目标占比 + 来源给了吗？

## 8. 常见问题（FAQ）

**Q：我不会写 JSON，怎么办？**
不用你写。你把第 5、6 节的"大白话"发给我，我负责翻译成 JSON；你只要在出表前核对我列出的口径。

**Q：数据里多选题是 0/1 一列一个选项，行吗？**
行。告诉我"这几列是同一道题、1 代表选中"即可。

**Q：选项文字和数据里不一样（问卷写"男"，数据是"Male"）怎么办？**
我会保留数据里实际出现的文字来计数，并给你一条警告，不丢数；你确认用哪个即可。

**Q：为什么要"先校验不落盘"？**
防止出错了还要重跑。校验这步能先看到删人数、分组数、质量警告，改对了再正式出表。

**Q：出表数字和 Base 对不上？**
一般是有未配置的选项文字、或某题分母设错了。我会看 `quality_checks` / `table_checks` 定位，不直接忽略。

**Q：加权不收敛？**
通常是目标人群没样本、目标冲突、或截尾范围太窄。我会先检查再决定怎么改，不会把没收敛的权重当成有效结果交给你。
